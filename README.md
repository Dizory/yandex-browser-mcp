# Yandex Browser MCP

Управление **уже открытым Яндекс Браузером** из агента с поддержкой MCP.
Обычные вкладки, текущая авторизация, клики, клавиатура, чтение страниц и
редактирование через интерфейс сайта. Без отдельного рабочего профиля и
подтверждения каждого действия.

```text
MCP-клиент → локальный Node.js сервер → расширение → твои вкладки
```

Проект состоит из расширения Manifest V3 и сервера. В самом проекте нет LLM,
API-ключей модели или облачного посредника. Агент и его провайдер определяются
тем приложением, в котором ты подключишь MCP.

## Быстрый запуск

### Автообновление только расширения в Windows

Для установки в `%LOCALAPPDATA%\YandexBrowserMCP\extension` предусмотрена отдельная задача Планировщика Windows. При входе в Windows и каждые 15 минут она ищет сборки `ext-build-*` в GitHub Releases. Пакет содержит только файлы расширения. Обновление MCP-сервера выполняется отдельно по твоему расписанию.

1. Установи GitHub CLI с командой `gh attestation verify`, войди через `gh auth login`. Для проверки происхождения пакета используется подпись GitHub Actions, привязанная к репозиторию, ветке `main` и workflow тестов.
2. Запусти из распакованного комплекта `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\enable-extension-updates.ps1`. Скрипт зарегистрирует и сразу запустит задачу `YandexBrowserMCP-ExtensionUpdates`.
3. При переходе со старой версии один раз нажми **Перезагрузить** на карточке расширения в `browser://extensions` после первой установки пакета. Оставь режим разработчика включённым. В дальнейшем расширение замечает смену сборки и перезагружается при ближайшей проверке, когда команды завершены.

Последний результат записывается в `%LOCALAPPDATA%\YandexBrowserMCPExtensionUpdater\last-run.log`, а предыдущая копия расширения — в соседнюю с `extension` папку `.extension-previous`. При неудачном запуске новой сборки отключи задачу, восстанови предыдущую папку под именем `extension` и перезагрузи расширение. Чтобы выключить автообновление, выполни `Disable-ScheduledTask -TaskName YandexBrowserMCP-ExtensionUpdates`.

При обновлении с 0.1 останови старый процесс MCP-сервера, обнови комплект, выполни `npm ci` и запусти сервер из обновлённого каталога. Перезагрузи распакованное расширение в `browser://extensions`. Проверь, что `/health` показывает версию `0.2.0`, а MCP-клиент получил новый список инструментов. Старый сервер может продолжать отвечать на том же порту до перезапуска.

**Установка по заданию агенту:** скачай [комплект для Windows](https://github.com/Dizory/yandex-browser-mcp/releases/latest)
и передай агенту текст из [AGENT_PROMPT.txt](AGENT_PROMPT.txt). Подробная процедура
для агента — [INSTALL_AGENT.md](INSTALL_AGENT.md).

В распакованном комплекте запусти `install.ps1` через PowerShell. Он установит
зависимости, запустит сервер и создаст настройки MCP с абсолютными путями.
Флаг `-RegisterCodex` добавит подключение в Codex. Расширение загружается через
`browser://extensions` агентом с доступом к интерфейсу или пользователем.

Для установки из исходников вручную:

Нужны Node.js 22+ и настольный Яндекс Браузер с поддержкой Manifest V3.

```sh
git clone https://github.com/Dizory/yandex-browser-mcp.git
cd yandex-browser-mcp
npm ci
npm start
```

На Windows можно запустить `start.cmd`: при первом запуске он установит
зависимости, затем запустит сервер. Окно сервера нужно оставить работающим.

Открой в Яндексе `browser://extensions`, включи режим разработчика, нажми
**Загрузить распакованное расширение** и выбери папку `extension` из этого
репозитория. Это одноразовая установка; браузер останется в твоём текущем
профиле. В окне расширения будет виден статус соединения. Если в твоей версии
Яндекса загрузка распакованных расширений ограничена, это нужно проверить
отдельно — обход ограничений браузера проект не устанавливает.

Состояние сервера: <http://127.0.0.1:37891/health>.
`"connected":true` означает, что расширение подключено.

## Подключение агента

Адрес MCP (Streamable HTTP):

```text
http://127.0.0.1:37891/mcp
```

Для Codex добавь в `config.toml`:

```toml
[mcp_servers.yandex_browser]
url = "http://127.0.0.1:37891/mcp"
```

Или выполни:

```sh
codex mcp add yandex_browser --url http://127.0.0.1:37891/mcp
```

Если клиент поддерживает только stdio, укажи полный путь к `server/stdio.js`:

```json
{
  "mcpServers": {
    "yandex_browser": {
      "command": "node",
      "args": ["C:/path/to/yandex-browser-mcp/server/stdio.js"]
    }
  }
}
```

Сервер `npm start` нужен и для stdio: переходник соединяет агента с тем же
локальным сервером. Несколько MCP-клиентов могут подключаться одновременно.
На каждой вкладке команды выполняются последовательно, но последовательности
из нескольких вызовов разных агентов могут перемежаться — распределяй им
разные вкладки. Подключается один экземпляр расширения за раз.

Пример задания агенту:

> Найди открытую вкладку с CRM. Прочитай карточку текущего клиента и заполни
> комментарий «Перезвонить завтра». Сохрани изменение.

## Команды

| Инструмент | Назначение |
|---|---|
| `browser_tabs` | Список вкладок, адреса и идентификаторы |
| `browser_open` | Открыть HTTP(S)-страницу |
| `browser_activate` | Выбрать вкладку и окно |
| `browser_close` | Закрыть вкладку |
| `browser_navigate` | Перейти по адресу в существующей вкладке |
| `browser_snapshot` | Текст страницы и элементы с CSS-селекторами |
| `browser_find` | Найти элемент по части названия и необязательной роли, получить до 10 совпадений с селекторами |
| `browser_click` | Клик по селектору или координатам; двойной/правый клик |
| `browser_type` | Ввод текста, в том числе в contenteditable; замена содержимого |
| `browser_press` | Клавиша или сочетание: Enter, Tab, Control+A и др. |
| `browser_scroll` | Прокрутка страницы или вложенной области |
| `browser_screenshot` | PNG текущей видимой области вкладки |
| `browser_evaluate` | JavaScript-выражение в странице с ожиданием Promise |
| `browser_cdp` | Произвольная доступная команда Chrome DevTools Protocol |
| `browser_wait` | Дождаться текста, состояния элемента или адреса |
| `browser_read_region`, `browser_read_table`, `browser_read_form` | Прочитать область страницы, HTML-таблицу или поля формы |
| `browser_fill_form`, `browser_select`, `browser_set_checked` | Заполнить поля без отправки, выбрать вариант, установить состояние флажка |
| `browser_inspect` | Проверить видимость и доступность элемента, узнать, что его перекрывает |
| `browser_hover`, `browser_drag` | Навести указатель или перетащить элемент |
| `browser_frames` | Получить ID фреймов. Передай `frameId` в `snapshot`, `find` или команду для чтения и заполнения формы |
| `browser_wait_download`, `browser_upload_file` | Дождаться конкретной загрузки или прикрепить локальный файл по абсолютному пути |
| `browser_history` | Назад, вперёд или обновить вкладку |
| `browser_diff` | Получить `snapshotId`, а при следующем вызове сравнить с ним состояние той же вкладки |

Начинай с `browser_tabs`. Если знаешь название кнопки, вызови, например,
`browser_find` с аргументами `{"tabId":7,"name":"Сохранить","role":"button"}`,
подставив ID своей вкладки. Передай выбранный `selector` в `browser_click`.
Если совпадений несколько, уточни цель по снимку страницы. Для обзора
страницы используй `browser_snapshot`. После переходов и изменения
страницы запрашивай новый снимок. Для таблиц с canvas используй screenshot,
координаты и клавиатуру; для специфичных операций — evaluate/CDP. Обычный
снимок читает главный документ, максимум 300 элементов и по умолчанию 20 000
символов. `maxChars` увеличивает лимит текста до 100 000. Неподгруженные строки,
вложенные фреймы и закрытые Shadow DOM не превращаются автоматически в текст.

Клик и клавиатура используют CDP Input, поэтому события приходят сайту как
браузерный ввод. Выбор по CSS требует единственного подходящего элемента.
Это важно для чатов и таблиц, которые игнорируют простой DOM `.click()`.

## Вход и пароли

### Google Таблицы

Для Google Таблиц у DSH есть отдельные инструменты `sheets_*`. Локальный сервер обращается к официальному Google Sheets API. Передавай URL документа или ID в параметре `spreadsheet`; вкладку можно закрыть. Для диапазонов указывай имя листа и адрес ячеек. Фрагмент `gid` в ссылке не определяет целевой лист.

| Инструмент | Действие |
|---|---|
| `sheets_info` | Получить названия листов, ID и размеры |
| `sheets_read` | Прочитать один или несколько диапазонов. Режим `FORMULA` возвращает формулы, `UNFORMATTED_VALUE` — исходные значения |
| `sheets_write` | Записать значения в один или несколько прямоугольников за один запрос |
| `sheets_append` | Добавить строки в конец таблицы. Ответ содержит фактический адрес записи |
| `sheets_clear` | Очистить значения выбранных ячеек с сохранением форматирования |
| `sheets_add_sheet`, `sheets_create` | Добавить лист или создать документ |

Например, после `sheets_info` DSH может передать в `sheets_write`:

```json
{"spreadsheet":"ID_ДОКУМЕНТА","updates":[{"range":"'Заказы'!A2:C2","values":[["Заказ 17",4,true]]}]}
```

По умолчанию запись использует `RAW`. Для формул добавь `"input":"USER_ENTERED"`. Значение `null` пропускает ячейку, а пустая строка очищает её. Данные должны помещаться в указанный прямоугольник. Для чтения или очистки можно запросить до 10 000 ячеек за вызов. После обрыва связи сначала прочитай результат, особенно перед повторным `sheets_append`.

**Подключение личного аккаунта.** В своём проекте Google Cloud включи Google Sheets API, настрой экран согласия OAuth и создай OAuth-клиент типа **Desktop app**. Если приложение в режиме Testing, добавь свой аккаунт в список тестовых пользователей. Скачай JSON клиента за пределы каталога проекта. Из каталога сервера выполни:

```powershell
npm run sheets:login -- "C:\путь\к\desktop-client.json"
```

Открой ссылку, которую команда напечатает в терминале, выбери аккаунт и подтверди доступ к Google Таблицам. После возврата в терминал должны появиться слова `Google Sheets connected`. Сервер читает данные авторизации из `%LOCALAPPDATA%\yandex-browser-mcp\google-user.json` в профиле пользователя Windows. Для отзыва доступа используй настройки подключённых приложений аккаунта Google и удали этот файл. Не пересылай JSON в чат и не включай его в ZIP. [Настройка OAuth для desktop-приложений](https://developers.google.com/identity/protocols/oauth2/native-app) · [Области доступа Sheets API](https://developers.google.com/workspace/sheets/api/scopes)

**Сервисный аккаунт.** Можно дать его адресу доступ только к нужной таблице и задать `GOOGLE_APPLICATION_CREDENTIALS` для процесса сервера. Значением должен быть путь к JSON-ключу за пределами проекта. Перезапусти сервер, чтобы он получил переменную окружения. Она имеет приоритет над личным входом. Права на создание новых документов зависят от аккаунта и хранилища Google.

### Вход на сайты в браузере

Уже выполненный вход используется автоматически. Клик в поле может вызвать
обычное автозаполнение браузера. Универсального управления меню менеджера
паролей, системным подтверждением и MFA здесь нет: если браузер требует
твоего участия, заверши вход и продолжай работу с агентом.

Обычный snapshot не возвращает значения password-полей. Это удобное исключение
из вывода, **не изоляция секретов**: evaluate/CDP дают полный доступ к странице,
а снимок экрана показывает то, что отображается в ней. Данные, прочитанные
агентом, могут попасть к его LLM-провайдеру. Сервер не пишет содержимое страниц
в файлы или журналы и слушает только `127.0.0.1`.

## Проверка

```sh
npm test
```

Проверяются настоящий MCP-handshake, схемы инструментов, маршрутизация ответов
между клиентами, ошибки ввода, обрыв связи, timeout без повторения действия и
ответы с изображениями. Расширение проверяется отдельно в тестах его логики.

После запуска сервера и установки расширения:

```sh
npm run test:browser
```

Этот тест открывает **свою локальную страницу**, вводит русский текст,
нажимает кнопку, меняет ячейку, проверяет двойной клик, клавиатуру, прокрутку,
снимок экрана, CDP и переход. Затем закрывает свою вкладку. Реальные чаты и
документы тест не изменяет. Значение тестового password-поля проверяется на
отсутствие в snapshot.

## Если что-то не работает

- `Browser extension is not connected`: запусти сервер, включи расширение,
  нажми переподключение в его окне. При перезапуске сервера оно переподключается.
- Порт занят: проверь `/health`. Если сервер уже запущен, используй его.
- Ошибка debugger: служебные страницы браузера и страницы других расширений
  могут быть недоступны; открытые DevTools могут мешать подключению.
- После ошибки или timeout сначала прочитай страницу: действие могло успеть
  выполниться. Сервер не повторяет изменения автоматически.
- Изменения исходников расширения требуют кнопки перезагрузки на странице
  `browser://extensions`; изменения сервера — его перезапуска.
- MCP не делает агента постоянно работающим. Для непрерывного наблюдения за
  чатом нужен работающий агент с циклом проверки или планировщик его клиента.
- Удалённый облачный агент не видит `127.0.0.1` твоего компьютера. В этой версии
  подключение рассчитано на MCP-клиенты, работающие локально.

Протокол между сервером и расширением описан в [PROTOCOL.md](PROTOCOL.md).

Чтобы собрать ZIP-комплект и SHA256: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/package.ps1`.
Результат появится в `artifacts`. В архив входят исходники, тесты и инструкции;
`node_modules`, локальные настройки MCP, журналы и данные браузера не включаются.
