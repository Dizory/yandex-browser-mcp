# Установка другим агентом (Windows)

Цель: подключить MCP-клиент к обычному профилю Яндекс Браузера пользователя и
проверить команды. Установщик включает сервер и файлы расширения. Само
расширение загружается через интерфейс браузера; наличие файлов на диске не
означает, что оно установлено.

## 1. Получи комплект

Репозиторий: https://github.com/Dizory/yandex-browser-mcp

Из [последнего релиза](https://github.com/Dizory/yandex-browser-mcp/releases/latest)
скачай `yandex-browser-mcp-windows.zip` и `SHA256SUMS.txt`. Сверь SHA256 через
`Get-FileHash -Algorithm SHA256`. Распакуй в постоянную папку, например
`$env:LOCALAPPDATA\YandexBrowserMCP`. Архив содержит файлы непосредственно в
корне, без дополнительной папки. Git для установки из ZIP не нужен.

Не распаковывай поверх неизвестной существующей установки. При повторной
установке сначала проверь её каталог, `/health` и запись MCP. Сохрани путь уже
загруженного расширения: Яндекс продолжает читать файлы из выбранного каталога.
Обновление работающей старой версии в этой процедуре не автоматизировано.

Нужны **Windows, Node.js 22+ с npm, настольный Яндекс Браузер**. Установщик
работает в Windows PowerShell 5.1 и PowerShell 7. Если Node.js или браузера
нет, установи их из официальных источников в пределах разрешений пользователя:
[Node.js](https://nodejs.org/), [Яндекс Браузер](https://browser.yandex.ru/).
После установки Node.js обнови PATH текущего процесса либо открой новый терминал.

## 2. Установи сервер и настрой MCP

Из корня распакованного комплекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1
```

Если настраиваешь **именно Codex**, используй:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\install.ps1 -RegisterCodex
```

Скрипт выполнит `npm ci`, запустит сервер скрытым процессом на
`http://127.0.0.1:37891/mcp` и запишет результат в
`artifacts/install-result.json`. В нём есть абсолютный `extensionPath` и пути
к готовым примерам `mcp-http.json` / `mcp-stdio.json`. Здоровый работающий мост
используется повторно; чужой процесс на порту не завершается.

`-RegisterCodex` использует установленный CLI `codex`. Существующая включённая
HTTP-запись с тем же адресом сохраняется. При другом адресе, отключённой записи
или stdio-настройке установщик останавливается с объяснением: проверь текущую
конфигурацию и при необходимости запусти установщик без `-RegisterCodex`.
Он не заменяет весь файл настроек клиента и не регистрирует MCP у других агентов.

Для другого клиента прочитай его актуальный формат настроек и добавь
**одну** запись `yandex_browser`, сохранив остальные. Предпочтительно Streamable
HTTP с адресом `http://127.0.0.1:37891/mcp`; универсального JSON-формата для всех
клиентов нет, поэтому `mcp-http.json` — пример, а не файл для безусловной замены.
Если клиент понимает только stdio, используй абсолютные `command` и `args` из
`mcp-stdio.json`; локальный HTTP-сервер всё равно должен работать.

Перезагрузи подключения MCP клиента, если это нужно. Не выполняй OAuth-login:
этот локальный сервер его не использует. Облачному клиенту без доступа к
компьютеру пользователя такой localhost-адрес недоступен.

## 3. Загрузи расширение

Используй доступный тебе инструмент управления браузером/рабочим столом:

1. Найди обычное окно Яндекс Браузера пользователя.
2. Открой `browser://extensions`.
3. Включи «Режим разработчика», если он ещё выключен.
4. Нажми «Загрузить распакованное расширение».
5. Выбери **точный `extensionPath`** из результата установщика.
6. Убедись, что «Yandex Browser MCP Bridge» включён.

Если уже есть рабочее подключение, сначала проверь существующее расширение;
не загружай второй экземпляр без необходимости. Проект поддерживает одно
подключённое расширение и несколько MCP-клиентов.

Если инструмент не может управлять этой страницей, попроси пользователя
выполнить только шаги загрузки и передай полный путь. Не выдавай выполненную
установку сервера за успешную установку расширения. Не закрывай браузер с
рабочими вкладками и не создавай отдельный профиль ради установки.

Установка через корпоративные политики не является универсальным способом
для личного Windows-компьютера: у Яндекса принудительная установка имеет
[ограничения управления устройством](https://browser.yandex.ru/support/browser-corporate/ru/policy/extension-install-forcelist).
Этот комплект использует загрузку распакованного расширения.

## 4. Подтверди результат

```powershell
Invoke-RestMethod http://127.0.0.1:37891/health
npm run test:browser
```

Успех означает всё перечисленное:

- `/health` возвращает `name=yandex-browser-mcp`, `connected=true`.
- MCP-клиент получает 29 инструментов `browser_*` и 7 инструментов `sheets_*`. Проверь `browser_tabs`; для проверки `sheets_info` нужны отдельная авторизация Google и ссылка на документ.
- `npm run test:browser` завершается с кодом 0 и строкой `PASS`.

Тест работает со своей локальной страницей и закрывает свою вкладку. Если
есть ошибка, прочитай её и исправь причину; не отправляй тестовые сообщения
в реальные переписки. Значение `connected=true` само по себе не подтверждает,
что клиент агента перезагрузил MCP-конфигурацию.

## После перезагрузки компьютера

Автозапуск в ОС не создаётся. Сервер запускается скрыто из каталога установки:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-bridge.ps1
```

Либо пользователь запускает `start.cmd` и оставляет его окно работающим.
Повторно устанавливать расширение и регистрацию MCP не нужно. Не удаляй
каталог установки. Для удаления отключи регистрацию MCP в своём клиенте и
удали расширение через интерфейс Яндекса; сервер останавливай только после
проверки принадлежащего этой установке процесса.
